# Fixed Income Order Execution System

A capstone project for a broker-dealer style fixed income trading platform covering Indian bonds, G-Secs, T-Bills, NCDs, CDs, CPs, portfolios, trades, and admin workflows.

Built with Next.js, TypeScript, Tailwind CSS, Recharts, and Lucide icons. The application currently uses static local JSON data and does not have a backend or database.

Project repository: [github.com/AshishSatavase/Capstone_Project](https://github.com/AshishSatavase/Capstone_Project)

The complete product brief and requirements are in [prompt.MD](prompt.MD). Read it before starting work.

## Project Structure

```text
app/          Routes and page layouts (Next.js App Router)
components/   Reusable UI, layout, order, and chart components
data/         Static JSON data used by the demo application
lib/           Types, data-access functions, theme, and utilities
public/       Public assets
scripts/      Data-generation scripts
```

All static application data lives in the [data](data) folder. For any data-related feature, first check the relevant JSON file there. Update data in `data/` when needed, then use the typed functions in [lib/data.ts](lib/data.ts) rather than importing JSON directly into components. Add or update interfaces in [lib/types.ts](lib/types.ts) when a data shape changes.

## AI-Assisted Development Workflow

Use AI tools to plan and implement features, but review and verify every generated change.

### 1. Plan the idea with Claude

Read [prompt.MD](prompt.MD), describe your feature idea in Claude, and ask Claude to convert it into a clear implementation prompt. Include the affected route, data requirements, expected behavior, design constraints, and acceptance criteria.

### 2. Implement with Copilot or Codex

Open the project in VS Code, sign in to GitHub, and use the GitHub Copilot Chat **Agent** window. You can also use ChatGPT's IDE integration or Codex. Give the tool the prompt generated by Claude along with [prompt.MD](prompt.MD), and ask it to inspect the existing code before making a focused change.

Useful context to include:

```text
Read prompt.MD and AGENTS.md first. Work only on [feature]. Reuse existing components and data-access patterns. Keep the UBS-inspired white, black, red, and positive-green design system. Make the smallest focused change, then tell me which files changed and how to verify it.
```

## Contributing

1. Create a branch for your feature or fix.
2. Keep the change focused and follow the existing component and data-access patterns.
3. Check the UI and review the generated diff before opening a pull request.
4. Explain what changed, why it changed, and how you tested it. Include screenshots for visual changes.

Do not commit secrets, API keys, `.env` files, `node_modules`, or build output.

## Conventions

- Reuse `Button`, `Badge`, `Card`, `DataTable`, `SectionHeader`, chart wrappers, and related components.
- Preserve the institutional visual language: white backgrounds, black text, UBS red for emphasis and negative values, and green only for positive values.
- Use TypeScript types instead of `any` where practical.
